<objective>
Close the MCP `.well-known/oauth-protected-resource` 404 advisory: FastMCP's `TokenVerifier(base_url=...)` advertises a `resource_metadata` URL on 401 WWW-Authenticate that currently 404s. Serve a minimal RFC 9728-compliant stub at that exact path.

Purpose: Stop the advertised-URL 404 without inventing a fake authorization server. RFC 9728 §7.7-7.8 warns that fabricated `authorization_servers` entries create SSRF / phishing risk; the stub omits that field entirely. Project stays on Phase 2 static shared bearer (D-12).

Output: New `@mcp.custom_route` in `mcp-server/app/health.py` serving the stub JSON; extended `mcp-server/tests/test_auth.py` with schema + 404-closed assertions; a code comment documenting D-12 (static bearer remains).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public MCP HTTP app -> untrusted MCP client | Anyone reaching mcp.puzzlesstool.online can GET the well-known endpoint; response must not leak internal URLs or promise an AS that does not exist |
| WWW-Authenticate advertisement -> client fetch | Client may follow the advertised resource_metadata URL; the response must be RFC 9728-compliant to avoid confusing clients or training them to accept fake AS entries |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05.1-04 | Spoofing / SSRF | well-known response `authorization_servers` field | high | mitigate | Omit `authorization_servers` from the stub JSON entirely (D-11, RFC 9728 §7.7-7.8). Test asserts key absent. Project stays on static bearer; no real AS to point at. |
| T-05.1-05 | Information Disclosure | well-known `resource` field leaking internal URL | medium | mitigate | `resource` derives from MCP_PUBLIC_BASE_URL only (never MCP_API_BASE_URL or internal docker hostnames); fallback to localhost is dev-only and matches auth.py advertisement. |
</threat_model>
