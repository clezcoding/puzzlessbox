# Phase 05.1: Code Review Report

**Reviewed:** 2026-08-08T14:12:00Z
**Depth:** standard
**Files Reviewed:** 8
**Status:** issues_found

## Summary

Phase 05.1 adds first-user MCP auto-bootstrap (`check_and_bootstrap_first_user`), wires it into `POST /internal/mcp-auth`, adds an RFC 9728 well-known stub on the MCP server, and disables `X-Powered-By` in Next.js. Core logic is sound: table lock prevents duplicate `mcp_clients` rows, prod refuses auto-generate, plaintext tokens stay out of `logger.*`, and integration/unit tests cover the main paths.

No blocker-level bugs or auth bypasses found. Four warnings: prod refuse can still insert `service_principals` before aborting MCP insert; dev stdout token may land in container logs; `hmac.compare_digest` length mismatch can 500; earliest-user selection on re-bootstrap edge case.

## Warnings

### WR-01: Prod refuse leaves partial `service_principals` row

**File:** `api/app/core/bootstrap.py:86-106`
**Issue:** `service_principals` INSERT runs before the `MCP_BOOTSTRAP_TOKEN` prod guard. When `ENV=prod` and `MCP_BOOTSTRAP_TOKEN` is empty but `SERVICE_BEARER_TOKEN` is set, the function logs an error and returns without inserting `mcp_clients`, yet the caller still `commit()`s — persisting a `service_principals` row with no matching `mcp_clients` row. D-02 wording ("returns without inserting") and plan truth #18 imply atomic refusal; tests only assert `mcp_count == 0`.
**Fix:** Move the prod token guard before any INSERT, or roll back / skip `service_principals` when MCP insert is refused:

```python
bootstrap_token = settings.MCP_BOOTSTRAP_TOKEN.strip()
if not bootstrap_token:
    if settings.is_prod:
        logger.error("Production MCP bootstrap blocked: bootstrap token env is empty.")
        return
    bootstrap_token = secrets.token_urlsafe(32)
    sys.stdout.write(f"\n[BOOTSTRAP] Generated local MCP_BOOTSTRAP_TOKEN: {bootstrap_token}\n")
    sys.stdout.flush()

# service_principals + mcp_clients inserts only after token is resolved
```

### WR-02: Dev generated token on stdout may reach container logs

**File:** `api/app/core/bootstrap.py:107-109`
**Issue:** Dev auto-generate writes the plaintext token to `sys.stdout`. In Docker/Coolify, stdout is collected into deployment logs — same disclosure surface D-03 mitigates for `logger.*`. CONTEXT notes dev may use stdout "or a 0600 file" but also warns against Coolify log streams; containerized local dev blurs that line.
**Fix:** Prefer a `0600` file under a known dev path (e.g. `.local/mcp-bootstrap-token`) with a one-line stdout hint pointing to the file path, or gate stdout write on `not settings.is_prod and sys.stdout.isatty()`.

### WR-03: `hmac.compare_digest` length mismatch can raise 500

**File:** `api/app/routers/internal.py:27`
**Issue:** `hmac.compare_digest(service_bearer, settings.SERVICE_BEARER_TOKEN)` raises `TypeError` when argument lengths differ. A malformed `X-Service-Bearer` header can surface as HTTP 500 instead of 401, leaking error-handling behavior and bypassing the intended auth rejection path.
**Fix:**

```python
expected = settings.SERVICE_BEARER_TOKEN
if (
    not service_bearer
    or len(service_bearer) != len(expected)
    or not hmac.compare_digest(service_bearer, expected)
):
    raise HTTPException(status_code=401, ...)
```

### WR-04: Re-bootstrap binds earliest user, not latest signup

**File:** `api/app/core/bootstrap.py:80-84`
**Issue:** When `mcp_clients` is empty but multiple `"user"` rows exist (manual table wipe, failed prior bootstrap), `ORDER BY "createdAt" ASC LIMIT 1` selects the oldest account — not necessarily the operator's intended owner. Rare ops edge case; no test coverage.
**Fix:** Document the behavior in bootstrap docstring, or scope bootstrap to users created after last wipe / require explicit `SERVICE_OWNER_ID` when users > 1.

## Info

### IN-01: Auto-generated dev token is not persisted outside DB hash

**File:** `api/app/core/bootstrap.py:107-127`
**Issue:** When `MCP_BOOTSTRAP_TOKEN` is empty in dev, a random token is generated, hashed into `mcp_clients`, and printed once to stdout. It is not written back to env or settings. Missing that stdout line leaves MCP auth broken until the row is deleted or env is set manually. Tests expect 401 for a placeholder hash — correct but operability footgun.
**Fix:** Document in bootstrap stdout message that the token must be copied to `.env` / Hermes config, or write to a dev-only `0600` file as plan allows.

### IN-02: `LOCK TABLE` on every first-boot auth attempt

**File:** `api/app/core/bootstrap.py:75`
**Issue:** `LOCK TABLE mcp_clients IN EXCLUSIVE MODE` runs on every `/internal/mcp-auth` call while the table is empty, serializing concurrent first-boot requests. Acceptable for first-boot; negligible once a row exists (early return still acquires lock until transaction end).
**Fix:** None required for v1; optional `NOWAIT` + retry for faster fail under contention.
