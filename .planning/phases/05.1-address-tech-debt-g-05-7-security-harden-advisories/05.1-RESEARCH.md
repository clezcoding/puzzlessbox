# Phase 05.1: Address Tech Debt: G-05-7 + Security Harden Advisories - Research

**Researched:** 2026-08-05
**Domain:** Security Hardening & Authentication Bootstrap
**Confidence:** HIGH

## Summary

This phase targets the resolution of outstanding technical debt from the Phase 5 / v1.0 milestone audit:
1. **Local MCP Bootstrap (G-05-7):** Currently, the local development stack fails to initialize the MCP server properly on fresh boots because the required database records mapping the service principal and the MCP client to a user do not exist. We resolve this by implementing a dynamic, zero-config auto-bootstrap routine. Whenever an empty `mcp_clients` table is encountered (or on the first MCP auth lookup), the system detects the single registered user, sets them as the owner, hashes the tokens, and inserts the necessary authorization records atomically.
2. **Production Security Harden Advisories:** We harden public-facing ingress paths on Coolify/Traefik by enforcing HTTP Strict Transport Security (HSTS) and stripping identifying metadata banners (`Server`, `X-Powered-By`). Next.js is configured to cease emitting `X-Powered-By`.
3. **RFC 9728 Well-Known Stub:** FastMCP's token verifier advertises a resource metadata discovery URL, which currently 404s. We close this gap by implementing a minimal RFC 9728-compliant metadata endpoint served directly by the MCP server at `/.well-known/oauth-protected-resource/mcp`.

**Primary recommendation:** Use dynamic auto-bootstrap on `/internal/mcp-auth` to catch both API-driven signups and Next.js Better Auth direct DB mutations, combined with Traefik Response Header middlewares to enforce transport security and strip banners at the ingress layer.

### Locked Decisions

#### Local MCP bootstrap (G-05-7)
*   **D-01:** Auto-bootstrap after successful first user — when `mcp_clients` is empty, create MCP client + service principal for that owner's UUID (Better Auth / first-user path, not only API `POST /auth/signup`).
*   **D-02:** Token source: prefer `MCP_BOOTSTRAP_TOKEN` from env. If env empty and `ENV=dev` (local only): generate once. **Prod: env token REQUIRED — refuse auto-generate.** Store SHA-256 hash only in DB (existing D-07 pattern).
*   **D-03:** **Never log plaintext token** (OWASP Logging / MCP01; Phase 2 D-07). Dev generate may print once to stdout or write a `0600` file — not `logger.info` / Coolify log streams.
*   **D-04:** Auto-set owner = first-user UUID for both `mcp_clients` and `service_principals` / `SERVICE_OWNER_ID` equivalent so MCP→API hop works without a second manual step. Guard: insert only when tables empty / count==0; use atomic count+insert.
*   **D-05:** Keep lifespan `ensure_mcp_client` / `ensure_service_principal` as complementary path when env vars are already set (compose/Coolify). Auto path covers the empty-env first-signup case.

#### HSTS
*   **D-06:** Set `Strict-Transport-Security: max-age=31536000; includeSubDomains` on Coolify/Traefik for each public host: `pbox.puzzlesstool.online`, `api.puzzlesstool.online`, `mcp.puzzlesstool.online`. No `preload` in v1.
*   **D-07:** Apply per FQDN — do **not** set apex `puzzlesstool.online` HSTS with `includeSubDomains` in this phase (avoids forcing HTTPS on unrelated subdomains). Leaf `includeSubDomains` only affects children of that leaf (usually none).

#### Server / X-Powered-By banners
*   **D-08:** Strip `Server` (and `X-Powered-By` if present) at Coolify/Traefik for all three public hosts.
*   **D-09:** WebApp: `poweredByHeader: false` in Next.js config (official opt-out of `X-Powered-By`).

#### MCP `.well-known/oauth-protected-resource` stub
*   **D-10:** Serve metadata at the path WWW-Authenticate already advertises: `/.well-known/oauth-protected-resource/mcp` (matches FastMCP `TokenVerifier` + `MCP_PUBLIC_BASE_URL` / G-05-5).

### Pattern 1: Dynamic Auto-Bootstrap Flow in `/internal/mcp-auth`
When the first MCP call is authorized, `/internal/mcp-auth` triggers an atomic check on the database. If no `mcp_clients` exist, it pulls the first registered user's ID, bootstraps a default client and service principal, and authorizes the request.

```python
# Source: [CITED: api/app/core/bootstrap.py]
def check_and_bootstrap_first_user(session: Session, settings: Settings) -> None:
    # Atomic count guard
    mcp_count = session.execute(text("SELECT count(*) FROM mcp_clients")).scalar_one()
    if mcp_count > 0:
        return

    first_user_id = session.execute(
        text('SELECT id FROM "user" ORDER BY created_at ASC LIMIT 1')
    ).scalar_one_or_none()
    if not first_user_id:
        return

    # Bootstrap Service Principal if empty
    sp_count = session.execute(text("SELECT count(*) FROM service_principals")).scalar_one()
    if sp_count == 0:
        service_bearer = settings.SERVICE_BEARER_TOKEN.strip()
        if service_bearer:
            sp_hash = hashlib.sha256(service_bearer.encode()).hexdigest()
            session.execute(
                text(
                    """
                    INSERT INTO service_principals (owner_id, name, bearer_hash, created_at)
                    VALUES (CAST(:owner_id AS uuid), 'mcp', :sp_hash, timezone('Europe/Berlin', now()))
                    ON CONFLICT (owner_id) DO NOTHING
                    """
                ),
                {"owner_id": first_user_id, "sp_hash": sp_hash},
            )

    # Bootstrap MCP Client
    bootstrap_token = settings.MCP_BOOTSTRAP_TOKEN.strip()
    if not bootstrap_token:
        if settings.is_prod:
            logger.error("Production MCP bootstrap blocked: MCP_BOOTSTRAP_TOKEN is empty.")
            return
        else:
            import secrets
            bootstrap_token = secrets.token_urlsafe(32)
            import sys
            sys.stdout.write(f"\n[BOOTSTRAP] Generated local MCP_BOOTSTRAP_TOKEN: {bootstrap_token}\n")
            sys.stdout.flush()

    mcp_hash = hashlib.sha256(bootstrap_token.encode()).hexdigest()
    session.execute(
        text(
            """
            INSERT INTO mcp_clients (id, owner_id, bearer_hash, status, expires_at, created_at)
            VALUES (
                gen_random_uuid(),
                CAST(:owner_id AS uuid),
                :mcp_hash,
                'active',
                NULL,
                timezone('Europe/Berlin', now())
            )
            """
        ),
        {"owner_id": first_user_id, "mcp_hash": mcp_hash},
    )
```

### Pattern 2: Custom RFC 9728 Well-Known Stub Route in FastMCP
FastMCP ASGI apps support adding customized HTTP endpoints through `@mcp.custom_route`. This is used to serve the OAuth protected resource metadata payload.

```python
# Source: [CITED: mcp-server/app/health.py]
@mcp.custom_route("/.well-known/oauth-protected-resource/mcp", methods=["GET"])
async def rfc9728_stub_route(request) -> JSONResponse:
    # Determine the public URL of the resource
    settings = get_settings()
    base_url = settings.mcp_public_base_url or "http://localhost:8001"
    # Construct RFC 9728 compliant JSON
    return JSONResponse(
        {
            "resource": f"{base_url.rstrip('/')}/mcp",
            "bearer_methods_supported": ["header"],
        }
    )
```

### Anti-Patterns to Avoid
*   **Plaintext token leakage in logs:** Never print or log raw `MCP_BOOTSTRAP_TOKEN` or `SERVICE_BEARER_TOKEN` via standard loggers (`logger.info`), as these streams are routed directly to Coolify stdout logs which are accessible to unauthorized users or saved in raw log archives.
*   **Apex Domain HSTS enforcement:** Enforcing `includeSubDomains` on the apex domain `puzzlesstool.online` would force HTTPS on unrelated services running on sibling subdomains, potentially breaking non-HTTPS staging sites or tools. Keep HSTS scopes restricted to the leaf FQDN level only.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Header management | Custom HTTP Python middleware headers | Traefik Response Header Middleware | Gateway-level handling is significantly faster, safer, and does not require touching application runtimes. |
| OAuth discovery | Custom Authorization Server | Minimal RFC 9728 Stub | We use simple static bearer auth in v1. Building a full OAuth server introduces massive attack surface, SSRF risks, and complexity. |

**Key insight:** Keeping downstream application layers simple by using network gateway features (like Traefik middlewares) guarantees that security policies cannot be bypassed at the application level.

## Common Pitfalls

### Pitfall 1: Dynamic Bootstrap Race Condition
**What goes wrong:** Multiple HTTP requests arriving simultaneously during the first-boot experience could trigger multiple parallel bootstrap routines, resulting in duplicate key insert failures or primary key collisions.
**Why it happens:** Non-atomic checks for user presence and `mcp_clients` rows allow race windows.
**How to avoid:** Utilize atomic SQL operations and lock checks (`SELECT count(*) FROM mcp_clients`) inside a database transaction, combined with an empty-table guard.

### Pitfall 2: Traefik Header Casing & Stripping Syntax
**What goes wrong:** Traefik does not strip the headers correctly or fails to load because of invalid custom label formatting.
**Why it happens:** Traefik requires empty assignments (`Header-Name=`) to strip custom headers. Correct syntax must be used:
`traefik.http.middlewares.strip-headers.headers.customResponseHeaders.X-Powered-By=`
`traefik.http.middlewares.strip-headers.headers.customResponseHeaders.Server=`
