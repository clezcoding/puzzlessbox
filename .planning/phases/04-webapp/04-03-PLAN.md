## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Next.js Client (DnD) | Client-side state; keine Server-Validierung nötig |
| Next.js Client → FastAPI | PATCH /items/{id}, /categories/{id} mit Session-Cookie; API validiert owner_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-13 | Tampering | optimistic move bypass | high | mitigate | API validiert owner_id + RLS; UI revert bei 401/403/500; kein blindes Vertrauen auf Client-state |
| T-04-14 | Information Disclosure | item modal cross-tenant | high | mitigate | API 404 bei fremdem item_id; Modal öffnet nur mit lokaler Item-Referenz aus geladenem Board |
| T-04-15 | Tampering | bulk move sequential PATCH | medium | mitigate | owner_id-Check pro PATCH; progress toast bricht bei erstem 403/404 ab; keine partial-state-Korruption (revert verbleibende) |
| T-04-16 | Denial of Service | DnD rapid drag spam | low | accept | Debounce auf API-Call; optimistic UI puffert; keine Server-Überlastung bei normalem User-Verhalten |
| T-04-17 | Tampering / XSS | category name in panel | medium | mitigate | React text binding sanitized; maxLength=40; kein dangerouslySetInnerHTML |
| T-04-18 | Tampering | 412 conflict "Behalten" force-PATCH | medium | mitigate | Server-seitige ETag-Bypass-Validierung nur für authentifizierten owner; force-PATCH ohne ETag nur wenn Client 412 bestätigt hat; Audit-Log für overrides |
</threat_model>
