<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hermes-VPS → MCP-Server | Untrusted network; Bearer-Token über HTTPS, 401 bei fehlendem/falschem Token (Phase 2) |
| MCP-Server → API | Interner Service-Bearer + X-Owner-Id Header; owner_id aus Access-Token-Claims |
| API → PostgreSQL | RLS / owner_id-Filter auf jeder Query |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | MCP_BEARER in Quellcode/.git | high | mitigate | Plugin lädt Token nur via env (D-12 setup script, .gitignore); kein Hardcode in items.py oder Plugin-Quellen |
| T-03-02 | Elevation of Privilege | discard_item Cross-Tenant | high | mitigate | owner_id aus get_access_token().claims, API filtert owner_id + RLS; fremde draft_id → 404 |
| T-03-03 | Tampering | Hermes-Cron als 30s-Timer | high | mitigate | Plugin treibt Timer nicht (Spike 001 INVALIDATED); API DraftTimeoutManager bleibt Autorität; Plugin pollt nur status |
| T-03-04 | Spoofing | confirm nach auto_saved | medium | mitigate | confirm_draft WHERE status IN ('draft','auto_saved') → idempotent 200 (D-08); kein 404/409 bei später Bestätigung |
| T-03-SC | Tampering | pip installs (httpx [SUS]) | high | mitigate | Package-Legitimacy-Audit in RESEARCH.md; httpx als [SUS] markiert aber manuell verifiziert (offizielle encode/httpx); pydantic [OK] |
