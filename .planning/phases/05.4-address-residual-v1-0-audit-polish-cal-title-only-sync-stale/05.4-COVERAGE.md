## dbhub Dual-Source Posture (D-07, D-08)

Both **local** and **coolify/prod** Postgres sources remain available. Agents choose `execute_sql_local` vs `execute_sql_coolify` (and `search_objects_local` vs `search_objects_coolify`) by MCP tool name knowingly — no remove-coolify mandate, no force-readonly mandate (D-07).

- `dbhub.toml` remains **gitignored** — see `.gitignore` line 53 (`dbhub.toml`).
- Dual-source posture is defined in `dbhub.toml` itself:
  - `[[sources]]` with `id = "local"` and `id = "coolify"`
  - `[[tools]]` binding `execute_sql` and `search_objects` to each source (full RW on both)
- Runtime MCP tool names (`execute_sql_local`, `execute_sql_coolify`, `search_objects_local`, `search_objects_coolify`) are **derived by dbhub** from `[[tools]]` `name` + `source` pairs — **not** declared as literals in `.cursor/mcp.json` (which only starts dbhub with `--config dbhub.toml` and sets `DATABASE_URL_COOLIFY` env).
- No credential-setup redesign (D-08): `.cursor/mcp.json` env / `DATABASE_URL_COOLIFY` posture unchanged; no `mcp.json.example` required this phase.
