## Implementation Decisions

### Title-only Calendar sync
- **D-01:** When both `starts_at` and `ends_at` are null on Google create/sync, derive a timed window: `start = now (UTC)`, `end = start + 1 hour`. Persist the derived times on the local event row and include Google `dateTime` start/end in the insert body. Do **not** skip sync and do **not** use all-day (`date`) schema for this path. — **Reversibility:** costly — derived times become real calendar data users may edit; changing default duration later does not rewrite past events
- **D-02:** Keep existing create-on-edit / PATCH Google update path (05.2 D-13 / D-15) when the user later changes times — no retry queue, no new “sync pending” job system. — **Reversibility:** reversible
- **D-03:** UX: discreet modal line for sync/derived-time state (05.2 D-23 spirit); **no** card sync badge; **no** toast on every title-only capture. — **Reversibility:** reversible
- **D-04:** Regression coverage = unit/integration tests (null times → derived window + insert; provided times unchanged). No live Google E2E required for this phase. — **Reversibility:** reversible

### 05.1-VERIFICATION frontmatter
- **D-05:** Docs-only flip: set `05.1-VERIFICATION.md` frontmatter `status: passed` (clear `human_needed`) with evidence pointers to Phase 05.3 verification / `05.1-UAT` complete / live well-known 200. Do **not** require a new deploy/curl pass inside 05.4. — **Reversibility:** reversible
- **D-06:** Keep the `human_verification` block as audit trail; mark items done and link evidence. Do not delete the block; do not leave it reading as still open. — **Reversibility:** reversible

### dbhub tooling
- **D-07:** Keep **both** local and coolify/prod sources always available (dual RW as in local `dbhub.toml`). `dbhub.toml` remains gitignored (not tracked). Agents choose `execute_sql_local` vs `execute_sql_coolify` by tool name — no remove-coolify, no force-readonly mandate. — **Reversibility:** reversible
- **D-08:** No change to credentials setup (`.cursor/mcp.json` env / `DATABASE_URL_COOLIFY` posture stays as today). — **Reversibility:** reversible

### Hermes `schedule_autosave_poll` RuntimeWarning
- **D-09:** Fix **tests**: `create_task` mocks must await/close coroutines so no orphaned coro warning. Keep production `dialog.py` fire-and-forget `asyncio.create_task(schedule_autosave_poll(...))` pattern. — **Reversibility:** reversible
- **D-10:** Scope = only suites that trigger the warning (e.g. `hermes-plugin/tests/test_orchestration.py` and related `create_task` patches). No full Hermes test audit; no shared helper unless planner finds ≥3 identical call sites cheaply. — **Reversibility:** reversible
- **D-11:** Done when affected pytest files are green **and** output has no `RuntimeWarning: coroutine ... was never awaited`. Do not add global `filterwarnings = error` for the whole hermes-plugin package. — **Reversibility:** reversible
