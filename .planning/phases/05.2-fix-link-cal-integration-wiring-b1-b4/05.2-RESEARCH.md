## Summary

Diese Forschungsphase befasst sich mit der Behebung von Integrationslücken (Gaps B1–B4) zwischen der Hermes-Nachrichtenerfassung, der WebApp-Board-Ansicht und externen Diensten (Link-Scraper und Google Calendar). Derzeit erfolgen Link-Metadaten-Scrapes und Google Calendar-Einträge nur über isolierte, ungenutzte Endpunkte (`POST /links` und `POST /events`), während der reguläre Hermes-Erfassungspfad (`POST /drafts`) diese Wires überspringt.

Durch das asynchrone Kicken von Link-Scrapes im Hintergrund (`asyncio.create_task`) nach dem Speichern eines Entwurfs und die automatische Google-Calendar-Synchronisation beim ersten Übergang in einen board-sichtbaren Zustand (`auto_saved` oder `confirmed`) wird der Erfassungsfluss nahtlos geschlossen. Das WebApp-Board wird erweitert, um Lade- und Fehlerzustände für Link-Vorschauen (Spinnings, Fallbacks mit systemnativen `<img>` ohne Next.js-Domainbeschränkungen) und Synchronisationsfehler diskret und formschön im Einklang mit den Hallmark- und Emil-Design-Engineering-Richtlinien anzuzeigen.

**Primary recommendation:** Erstellung eines in-memory `LinkScrapeManager` nach dem Muster des bewährten `DraftTimeoutManager`, um asynchrone Hintergrund-Scrapes zu verwalten, redundante Scrapes zu stornieren und transiente Fehler mit 2 Auto-Retries zu behandeln. Synchronisation von Terminen über eine geteilte Hilfsfunktion `sync_local_event_to_google` bei Zustandsübergängen sowie nahtlose Integration in `PATCH /items` für konfliktfreie ETag-basierte Google-Calendar-Aktualisierungen.

### Anti-Patterns to Avoid
* **Abfragen von externen OG-Bildern über den Next.js-Image-Optimizer:** Das Öffnen von `remotePatterns` im Next.js-Server für beliebige fremde URLs birgt SSRF- und Performance-Risiken. Verwende native HTML `<img>`-Tags mit `referrerPolicy="no-referrer"` und `onError`-Handhabung im Client.
* **Erneutes Erstellen von Terminen bei nachträglichem Google-Sync:** Wenn ein Event noch keine `google_event_id` besitzt und aktualisiert wird, darf kein zweiter lokaler Event-Eintrag erzeugt werden. Synchronisiere stattdessen direkt auf die bestehende Tabellenzeile.

## Common Pitfalls

### Pitfall 1: In-Flight Task Loss on Restart
* **What goes wrong:** Da Scrape-Tasks im Arbeitsspeicher des FastAPI-Prozesses über `asyncio.create_task` verwaltet werden, gehen alle laufenden Tasks bei einem Server-Neustart verloren.
* **Why it happens:** Keine Speicherung des Task-Zustands in einer persistenten Queue-Tabelle (D-18).
* **How to avoid:** Akzeptiere diesen Verlust gemäß Entscheidung D-18. Die Link-Einträge verbleiben im Zustand `pending` und können vom Benutzer in der UI über die modale Schaltfläche „Vorschau erneut laden“ manuell angestoßen werden.

### Pitfall 2: Next.js Image Component Domain Error
* **What goes wrong:** Die Next.js `<Image>`-Komponente weigert sich, Bilder von nicht autorisierten externen Hostnamen zu rendern (wirft Runtime-Fehler).
* **Why it happens:** Next.js erzwingt aus Sicherheitsgründen standardmäßig eine strikte Bilddomain-Allowlist.
* **How to avoid:** Nutze standardmäßige `<img ... />` Elemente im Frontend für alle OG-Vorschauen auf Karten und in Modalen (D-29).

### Pitfall 3: ETag Concurrency Desync on Calendar Edit
* **What goes wrong:** Wenn Google Calendar-Einträge ohne korrekten ETag-Abgleich aktualisiert werden, kommt es zu Konflikten und dem versehentlichen Überschreiben externer Modifikationen.
* **Why it happens:** Ein Editierpfad im UI sendet keinen aktuellen ETag an die API.
* **How to avoid:** Reiche den `etag`-Wert im `PATCH /items/{id}` durch und fange `HTTPException(412)` im API-Client ab, um das Konflikt-Panel („Google hat / Du hast“) anzuzeigen (D-14).

## Code Examples

### 1. Synchroner Google-Sync-Trigger (Helper)
```python
# Source: [ASSUMED - api/app/services/calendar.py]
import uuid
from sqlmodel import Session
from app.models import Event, CalendarToken
from app.services.calendar import calendar_service

def sync_local_event_to_google(db: Session, owner_id: str, event_id: uuid.UUID) -> Event | None:
    event = db.get(Event, event_id)
    if not event or event.google_event_id:
        return event

    token = db.get(CalendarToken, uuid.UUID(owner_id))
    if not token or not token.selected_calendar_id:
        return event  # D-10: Skip, disconnected

    try:
        # Re-use calendar_service helper inside asyncio.to_thread or run synchronously
        body = {
            "summary": event.title,
            "description": event.summary,
        }
        if event.starts_at and event.ends_at:
            body["start"] = {"dateTime": event.starts_at.isoformat()}
            body["end"] = {"dateTime": event.ends_at.isoformat()}

        service = calendar_service._calendar_service(db, owner_id)
        remote = service.events().insert(calendarId=token.selected_calendar_id, body=body).execute()
        
        event.google_event_id = remote.get("id")
        event.etag = remote.get("etag")
        db.add(event)
        db.commit()
        db.refresh(event)
    except Exception as exc:
        # D-11: Soft-fail, write error details but don't crash core transaction
        event.sync_error = str(exc)
        db.add(event)
        db.commit()
    return event
```
