## Critical Issues

### CR-01: SSRF check misses IPv4-mapped IPv6 and `0.0.0.0`

**File:** `api/app/services/scraper.py:62-67`  
**Issue:** `_is_blocked_ip` only tests membership in listed networks. `ipaddress.IPv6Address('::ffff:127.0.0.1') in IPv4Network('127.0.0.0/8')` is `False`, so `http://[::ffff:127.0.0.1]/`, `http://[::ffff:10.0.0.1]/`, and `http://[::ffff:169.254.169.254]/` pass validation and reach Firecrawl/Camoufox. `0.0.0.0` is also not blocked. Draft-link + `POST /links` both call `scrape_service.scrape` → server-side fetch to internal targets.

**Fix:**
```python
def _is_blocked_ip(ip_str: str) -> bool:
    try:
        addr = ipaddress.ip_address(ip_str)
    except ValueError:
        return True
    if isinstance(addr, ipaddress.IPv6Address) and addr.ipv4_mapped is not None:
        addr = addr.ipv4_mapped
    if addr.is_private or addr.is_loopback or addr.is_link_local or addr.is_reserved or addr.is_multicast:
        return True
    if addr == ipaddress.ip_address("0.0.0.0"):
        return True
    return any(addr in network for network in _BLOCKED_NETWORKS)
```

### CR-02: Type-change away from event orphans Google Calendar event

**File:** `api/app/routers/items.py:102-105`, `api/app/routers/items.py:332-341`  
**Issue:** `_apply_type_change` `DELETE`s the `events` row (dropping `google_event_id`) without calling `calendar_service.delete_remote_event`. Post-commit sync still keys off **old** `current_type == ItemType.event`, then `db.get(Event, …)` returns `None` and returns — remote Google event left orphaned; local linkage permanently lost.

**Fix:** Before deleting an event row with `google_event_id`, delete remote (same as `delete_item`). After type change, sync using the **new** type only when still an event:
```python
had_google_id = None
if current_type == ItemType.event:
    event_row = db.get(Event, uuid.UUID(item_id))
    if event_row and event_row.google_event_id:
        calendar_service.delete_remote_event(db, owner_id, google_event_id=event_row.google_event_id)

# ... _apply_type_change / _update_item_fields ...

effective_type = payload.type if payload.type is not None else current_type
if effective_type == ItemType.event:
    _sync_event_after_local_update(db, owner_id, item_id, payload, force=force)
```

## Warnings

### WR-01: Cancelled scrape leaves status `scraping`

**File:** `api/app/services/link_scrape.py:178-179`  
**Issue:** `except asyncio.CancelledError: pass` writes no terminal status. If a scrape is cancelled without an immediate replacement job (or replacement fails before `_set_scrape_status("scraping")`), BoardCard shows endless spinner.

**Fix:** On cancel, only clear if this task still owns the slot — otherwise leave successor alone; if still owner, set `pending`/`failed`:
```python
except asyncio.CancelledError:
    if self._active_tasks.get(link_id) is asyncio.current_task():
        await self._set_scrape_status(link_id, owner_id, "pending")
    raise
```

### WR-02: `discard_draft` does not cancel in-flight link scrape

**File:** `api/app/routers/capture.py:232-263`  
**Issue:** Cancels timeout only. Background scrape may still `apply_scrape_to_link` on a discarded draft (title/metadata/`scrape_status`/`category_id` mutation after soft-delete).

**Fix:**
```python
timeout_manager.cancel_timeout(draft_id)
if item_type == ItemType.link:
    scrape_manager.cancel_scrape(draft_id)
```

### WR-03: `DraftTimeoutManager` unconditional `finally` pop races reschedule

**File:** `api/app/services/timeout.py:74-75`  
**Issue:** Cancelled task pops `_active_tasks[draft_id]` even when a newer task already owns that key — same race `LinkScrapeManager` already fixed. Orphaned timer cannot be cancelled; may autosave after confirm/reschedule edge cases.

**Fix:**
```python
finally:
    current = asyncio.current_task()
    if self._active_tasks.get(draft_id) is current:
        self._active_tasks.pop(draft_id, None)
```

### WR-04: `POST /links` awaits scrape without soft timeout

**File:** `api/app/routers/links.py:59`  
**Issue:** Async draft path wraps scrape in `asyncio.wait_for(..., SOFT_SCRAPE_TIMEOUT=12)`. Sync `create_link` awaits `scrape_service.scrape` bare — Firecrawl 8s + Camoufox 4s can stack; request hangs longer than draft path and has no `timed_out` terminal mapping.

**Fix:**
```python
try:
    scraped = await asyncio.wait_for(scrape_service.scrape(url), timeout=SOFT_SCRAPE_TIMEOUT)
except asyncio.TimeoutError:
    title, metadata, scrape_status = hostname, {...}, "timed_out"
else:
    title, metadata, scrape_status = scrape_fields_from_result(url, scraped)
```

### WR-05: BoardCard long-press timer recreated every render

**File:** `webapp/components/board/board-card.tsx:83-94`  
**Issue:** `longPressTimer = { current: null }` is not a ref. Re-render between `touchstart` and `touchend` loses the timeout handle — long-press may fire after gesture ended or leak timers.

**Fix:**
```typescript
const longPressTimer = useRef<ReturnType<typeof setTimeout> | null>(null);
```

### WR-06: Event PATCH commits locally before Google sync; disconnect breaks updates

**File:** `api/app/routers/items.py:338-341`, `api/app/services/calendar.py:207-211`  
**Issue:** `db.commit()` runs before `_sync_event_after_local_update`. After `disconnect()` tokens are gone but `events.google_event_id` remains. Later title PATCH commits locally, then `_load_credentials` raises `CALENDAR_NOT_CONNECTED` — client sees failure despite successful local write; no soft-skip unlike `delete_remote_event`.

**Fix:** If not connected / no selected calendar, skip remote update (keep local) or clear `google_event_id` on disconnect. Prefer soft-skip mirroring delete:
```python
if not connected:
    return
```
