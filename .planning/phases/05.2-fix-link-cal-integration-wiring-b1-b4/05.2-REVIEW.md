## Summary

Full-phase re-review of LINK async scrape, Google Calendar sync wiring, and OAuth Accept 415 exemption. Async scrape + board VIEW fields look coherent; OAuth Accept-skip paths are correct. One correctness blocker: soft-delete removes the Google event but restore keeps a stale `google_event_id`, so later edits hit a dead remote id. Remaining warnings: OAuth UX/error routing, silent sync failures, modal sync-miss state, SSRF TOCTOU, and draft scrape_status init.

## Critical Issues

### CR-01: Restore after soft-delete leaves dangling `google_event_id`

**File:** `api/app/routers/items.py:359-394`, `api/app/routers/items.py:397-423`  
**Issue:** `delete_item` calls `delete_remote_event` then soft-deletes the local row **without clearing** `google_event_id` / `etag`. `restore_item` only nulls `deleted_at`. Restored event still points at a deleted Google event. Later PATCH takes the “has `google_event_id`” branch in `_sync_event_after_local_update` and calls `update_event_with_etag` → Google 404 → `GOOGLE_CALENDAR_ERROR`, blocking local edits. Integration test `test_delete_item_with_google_event_id_calls_events_delete` asserts restore does **not** re-insert, locking in the gap.

**Fix:** Clear remote linkage on delete (or on restore), then let sync-miss / confirm path recreate:

```python
# in delete_item, after delete_remote_event succeeds (or always before soft-delete):
if item_type == ItemType.event:
    db.execute(
        text(
            """
            UPDATE events
            SET google_event_id = NULL, etag = NULL,
                deleted_at = timezone('Europe/Berlin', now()),
                updated_at = timezone('Europe/Berlin', now())
            WHERE id = CAST(:item_id AS uuid) AND owner_id = CAST(:owner_id AS uuid)
            RETURNING id
            """
        ),
        {"item_id": item_id, "owner_id": owner_id},
    )
```

Or on restore: clear `google_event_id`/`etag` and optionally call `sync_local_event_to_google`.

## Warnings

### WR-01: OAuth callback errors strand user on API host

**File:** `api/app/routers/calendar.py:25-39`  
**Issue:** `google_callback` redirects only on success. `exchange_code` / `upsert_tokens` failures surface as JSON on `api.*` after Google consent — no webapp recovery path.

**Fix:** Catch failures and redirect to `{WEBAPP_URL}/settings?calendar=error` (no sensitive details).

### WR-02: Client navigates to `authorization_url` without host allowlist

**File:** `webapp/lib/api/calendar.ts:14-18`  
**Issue:** `window.location.href = authorization_url` with no host check. Compromised API response / MITM → open redirect.

**Fix:**

```typescript
const host = new URL(authorization_url).hostname;
if (host !== "accounts.google.com") {
  throw new ApiError("INVALID_OAUTH_URL", "Ungültige OAuth-Weiterleitung.");
}
window.location.href = authorization_url;
```

### WR-03: Connect button allows double-submit

**File:** `webapp/components/settings/calendar-wizard.tsx:82-92`, `webapp/components/settings/calendar-wizard.tsx:201-203`  
**Issue:** No in-flight guard on “Mit Google verbinden”. Double-click → parallel OAuth states → flaky callback.

**Fix:** `connecting` state + `disabled={connecting}`; early-return if already connecting.

### WR-04: `WEBAPP_URL` default survives prod without startup guard

**File:** `api/app/core/config.py:20`, `api/app/routers/calendar.py:36-38`  
**Issue:** Default `http://localhost:3000` used if env unset. Callback stores tokens then redirects to localhost — connection looks broken in prod.

**Fix:** `@model_validator` rejecting localhost `WEBAPP_URL` when `ENV=prod`.

### WR-05: Modal Google sync CTA does not refresh `google_event_id`

**File:** `webapp/components/board/item-modal.tsx:192-206`, `webapp/components/board/item-modal.tsx:133-134`  
**Issue:** `handleGoogleSync` PATCHes `{ title }` (server may insert Google event) then `onUpdated({ ...item!, title })` without new `google_event_id`. `showSyncMiss` stays true for the open modal; user can re-click a no-op CTA until board poll refreshes props.

**Fix:** After successful sync, refetch board item (or return `google_event_id` from PATCH) and pass it through `onUpdated`.

### WR-06: `sync_local_event_to_google` swallows all failures

**File:** `api/app/services/calendar.py:368-381`  
**Issue:** Bare `except Exception:` rollbacks and re-commits local row with no `google_event_id`, no log, no error to caller. Confirm/autosave/PATCH report success while Google sync silently failed — sync-miss UI is the only signal, and only if client refreshes.

**Fix:** Log the exception at minimum; optionally surface a non-fatal `sync_status` / warning field on the response.

### WR-07: SSRF check is TOCTOU vs scraper fetch

**File:** `api/app/services/scraper.py:83-119`, `api/app/services/scraper.py:148-155`  
**Issue:** `validate_url_ssrf` resolves DNS once, then hands the URL to Firecrawl/Camoufox which resolve again. DNS rebinding can pass the check then hit private/link-local targets from the scraper network.

**Fix:** Prefer IP-literal fetch after resolve, or pin resolved address; have Firecrawl/Camoufox re-run the same SSRF policy; block redirects to private ranges.

### WR-08: Draft link create leaves `scrape_status` NULL

**File:** `api/app/routers/capture.py:102-108`, `api/app/routers/capture.py:171-173`  
**Issue:** `POST /links` sets `scrape_status="pending"`; draft link insert does not. Status stays `NULL` until background job reaches `_set_scrape_status(..., "scraping")`. Board card treats null as placeholder (not loading), so UI can flash wrong thumb state / skip spinner.

**Fix:** Set `scrape_status="pending"` on draft `Link` insert (same as `POST /links`).

### IN-03: Type-change to `event` does not trigger Google sync

**File:** `api/app/routers/items.py:260-286`, `api/app/routers/items.py:352-354`  
**Issue:** `_sync_event_after_local_update` only creates a remote event when `calendar_changed` (title/body/start/end). A type-only change to `event` leaves `google_event_id` null until a later field edit — sync-miss panel is the workaround, but easy to miss.

**Fix:** Treat type-change into `event` as sync-eligible (`force=True` path or `calendar_changed or type_changed`).
