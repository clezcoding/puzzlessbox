# Phase 05.2: Fix LINK/CAL integration wiring B1-B4 - Context

**Gathered:** 2026-08-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Close v1.0 milestone audit blockers **B1–B4**: wire existing scrape + Google Calendar services into the Hermes capture path and board/edit UI so LINK-01/02 and CAL-02/03 work end-to-end (not only on orphaned `POST /links` / `POST /events`).

In scope:
- B1: Async scrape after draft persist for link captures; shared scrape path with `POST /links`
- B2: Board VIEW + card show link URL + OG thumbnail (`summary`/`image`); Alembic VIEW migration
- B3: Push local events to Google on first board-visible status; soft-fail; keep `POST /events`
- B4: `PATCH /items` calendar sync with ETag/412; create-on-edit; delete→Google
- Supporting: scrape job mechanics, status enum + UI affordances, retry, OG `<img>` strategy
- UI for all new affordances MUST follow Hallmark + brand tokens + Emil craft + existing shadcn stack

Out of scope:
- New product capabilities (search, comments, Google Tasks CAL-04, full bidirectional calendar cron)
- External job queue (Redis/ARQ/Celery)
- Image proxy service
- Opening Next.js image optimizer to all hosts
- Changing scraper Coolify stack (Phase 5 D-04)
- Accepting LINK/CAL gaps and shipping milestone without fixes

<decisions>
## Implementation Decisions

### B1 — Scrape timing (LINK-01)
- **D-01:** Persist link draft first (URL + fallback title); run scrape **async** afterward; write metadata when done. — **Reversibility:** costly — capture latency/timeout coupling; undoing reintroduces sync scrape on draft path
- **D-02:** Background scrape soft-timeout **8–15s**; then `timed_out`/`failed` + hostname fallback per Phase 1 D-11. — **Reversibility:** reversible
- **D-03:** `POST /drafts` HTTP response stays immediate `{id, type}` — never wait on scrape. — **Reversibility:** reversible
- **D-04:** Keep orphaned `POST /links`; share scrape service logic with capture path (no deprecate). — **Reversibility:** reversible

### B2 — Board URL + thumbnail
- **D-05:** Board VIEW for links: `summary` = `url`; add `image` = `metadata->>'image'` (nullable). Extend API `BoardItem` + WebApp types. — **Reversibility:** costly — VIEW + client contract; needs Alembic DROP/CREATE VIEW
- **D-06:** Card thumbnail from `item.image` (not `summary.startsWith("http")`); muted placeholder when missing. — **Reversibility:** reversible
- **D-07:** Card meta line = truncated hostname/URL from `summary`. — **Reversibility:** reversible
- **D-08:** New Alembic revision recreates `board_items` VIEW (do not only hack `0006` in place). — **Reversibility:** one-way — migration applied in prod; rollback = another revision

### B3 — Calendar create trigger (CAL-02)
- **D-09:** Google `events.insert` on first transition to board-visible (`auto_saved` **or** `confirmed`) when `google_event_id` is null — idempotent. Sync onto **existing** local event row (do not invent a second Event via naive `create_event` that inserts a new row). — **Reversibility:** costly — capture→Google coupling
- **D-10:** No Google connect / no `calendar_id`: keep local event; skip Google (Phase 4 D-30 spirit). — **Reversibility:** reversible
- **D-11:** Google API error on create: still commit local board-visible status; record sync failure / leave `google_event_id` null; Hermes gets success. — **Reversibility:** reversible
- **D-12:** Keep `POST /events`; share sync helper with capture path. — **Reversibility:** reversible

### B4 — PATCH ↔ Google (CAL-03)
- **D-13:** Push only calendar fields: `title`, `summary`/body, `starts_at`, `ends_at`. `category_id` / `sort_order` stay local-only. — **Reversibility:** reversible
- **D-14:** Server uses stored `etag` + existing `update_event_with_etag`; return structured **412** + remote state (Phase 1 D-20). Force overwrite via existing client header `If-None-Match: *`. Do not require client `If-Match` rebuild. — **Reversibility:** costly — conflict contract with WebApp modal
- **D-15:** PATCH event without `google_event_id`: create-on-edit when Connected + calendar selected; else local only. — **Reversibility:** reversible
- **D-16:** Soft-delete with `google_event_id` → Google `events.delete`. Restore → local only (no auto-recreate). — **Reversibility:** reversible

### Scrape job mechanics
- **D-17:** Runner = `asyncio.create_task` after commit (same pattern as `timeout_manager`). No new queue dependency in 05.2. — **Reversibility:** reversible
- **D-18:** Process restart mid-scrape: accept loss; status may stay `pending`; retry/edit recovers. No durable job table in 05.2. — **Reversibility:** reversible
- **D-19:** Max **one** in-flight scrape per `link_id` (cancel/skip duplicates). — **Reversibility:** reversible
- **D-20:** `scrape_status` enum: `pending` | `scraping` | `ok` | `partial` | `timed_out` | `failed` | `skipped`. API stores codes; **UI never shows raw codes** — German labels/icons only. — **Reversibility:** costly — enum + UI mapping contract

### Sync / scrape status UI
- **D-21:** Feedback on **card (subtle) + modal (clearer)**. Board poll must include `scrape_status` + `image` for links. — **Reversibility:** costly — board API shape
- **D-22:** Card thumb slot: spinner for `pending`/`scraping`; muted placeholder for `timed_out`/`failed`; image for `ok`/`partial` when present — **no** loud badges. — **Reversibility:** reversible
- **D-23:** Google sync miss: discreet modal line when event lacks `google_event_id` (or sync error); **no** card sync badge. — **Reversibility:** reversible
- **D-24:** VIEW/read-model exposes `scrape_status` for links (`null` for other types). No N+1 detail fetch per card. — **Reversibility:** costly — VIEW/API

### UI design stack (mandatory)
- **D-25:** All new UI in this phase MUST use: **Hallmark** + `brand/tokens.css` / `VOICE.md` / Phase 0 brandkit as source of truth; **shadcn/ui-styling** (existing WebApp); **Emil design-eng** (subtle states, `<300ms` ease-out, `prefers-reduced-motion`, silent success); **premium-frontend** only for craft/micro-interaction quality — **not** dark-neon/generic AI defaults. — **Reversibility:** costly — visual contract for executors

### Retry after soft-fail
- **D-26:** Scrape job: exactly **2** auto-retries on transient failure, then end-status; **plus** manual modal action „Vorschau erneut laden“ for `failed`/`timed_out`/`partial`. — **Reversibility:** reversible
- **D-27:** Google create soft-fail: modal action „Mit Google synchronisieren“ when Connected; otherwise point to Settings calendar wizard. — **Reversibility:** reversible
- **D-28:** Retry UX: inline thumb/modal state; toast **only** on fail after manual retry; silent success (no success toast). — **Reversibility:** reversible

### OG images / next/image
- **D-29:** Link OG previews use native `<img>` (or passthrough custom loader) — **not** opening `remotePatterns` to all hosts. Keep `next/image` for brand/assets. — **Reversibility:** reversible
- **D-30:** OG `<img>` uses `referrerPolicy="no-referrer"`. — **Reversibility:** reversible
- **D-31:** `onError` → same muted placeholder as scrape fail (no layout jump). — **Reversibility:** reversible
- **D-32:** Keep existing `webapp/next.config.ts` `remotePatterns` list; OG path independent. — **Reversibility:** reversible

### Claude's Discretion
- Exact soft-timeout seconds within 8–15s
- Backoff delay between the 2 scrape auto-retries
- Whether `partial` requires title-only vs title+description without image
- Schema for storing calendar sync error (column vs metadata) as long as modal can detect “not synced”
- Helper naming / whether to refactor `calendar_service.create_event` vs add `sync_local_event_to_google`
- Test file placement (integration vs unit) covering B1–B4 wires
- Visual micro-details within Hallmark/Emil/brand tokens (spinner style, placeholder illustration vs solid muted)

### Checkpoint resolutions (plan-phase)
- **D-08 / apply-0007 (2026-08-08):** Operator approved. Apply Alembic `0007_board_items_link_fields` to **local DATABASE_URL and Coolify production Postgres**. Verify VIEW columns on both before closing tracer task.
